# Code Review 代码审查

对指定的代码变更进行结构化审查。按以下维度逐一检查：

## 1. 正确性
- 是否存在逻辑错误或边界条件遗漏？
- 异步代码是否有死锁风险（`.Result`、`.Wait()`）？
- 并发访问是否有竞态条件？

## 2. 安全性
- 是否存在 SQL 注入 / 命令注入 / 路径遍历？
- 用户输入是否经过验证和转义？
- API Key 或密钥是否可能泄露？

## 3. 性能
- 是否有不必要的内存分配（LINQ 重复枚举、大字符串拼接）？
- 是否有 N+1 查询或循环内调用外部 API？
- 是否有可缓存的重复计算结果？

## 4. 可维护性
- 命名是否清晰表达意图？
- 函数/方法是否过长（建议 < 50 行）？
- 是否有重复代码可以抽象？

## 5. 测试覆盖
- 新增代码是否有对应测试？
- 边界条件和异常路径是否覆盖？
- 测试是否可独立运行（不依赖外部状态）？

## 输出格式

```
## Code Review: {文件/变更范围}

### ✅ 通过
- ...

### ⚠️ 建议
- ...

### ❌ 必须修复
- ...
```
