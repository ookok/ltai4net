# Architecture Review 架构审查

对项目或模块进行架构评估，按以下维度分析：

## 1. 模块划分
- 模块职责是否单一清晰？
- 模块间的边界是否合理？
- 是否存在循环依赖？`A → B → C → A`

## 2. 依赖方向
- 高层模块是否依赖低层模块？（依赖倒置）
- 抽象是否稳定？具体实现是否可替换？
- 是否有接口/抽象层解耦？

## 3. 扩展性
- 新增功能需要改多少文件？
- 是否支持插件/策略/装饰器模式扩展？
- 配置是否外置（不硬编码）？

## 4. 技术债务
- 是否有标记为 `[Obsolete]` 或 `TODO` 的代码？
- 是否有大量注释掉的代码？
- 是否有重复的抽象层？

## 5. 数据流
- 数据在模块间的流转路径是否清晰？
- 是否有全局可变状态？
- 缓存策略是否合理？

## 输出格式

```
## Architecture Review: {模块/范围}

### 层级结构
{模块及依赖关系图}

### 发现
- ✅ 好的设计: ...
- ⚠️ 需要关注: ...
- ❌ 必须改进: ...

### 建议优先级
1. P0 - ...
2. P1 - ...
```
