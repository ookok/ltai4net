# Migration Plan 代码迁移

制定安全的框架/API/版本迁移方案。

## 1. 影响分析
- 识别所有使用了待替换 API 的代码
- 评估兼容性（源代码级 / 二进制级 / 行为变更）
- 列出所有受影响的文件

## 2. 迁移策略

| 策略 | 适用场景 | 风险 |
|------|---------|:----:|
| 逐步替换 | API 可共存 | 低 |
| 适配器模式 | 接口不兼容 | 中 |
| 一次性重写 | 小范围变更 | 高 |

## 3. 执行步骤
1. 添加新 API 引用（新旧共存）
2. 逐文件替换，保持编译通过
3. 运行测试验证每个步骤
4. 清理旧引用
5. 移除旧包/代码

## 4. 回滚方案
- 每步可单独回滚
- 使用 Git 分支隔离迁移工作
- 关键节点打 Tag

## 输出格式

```
## Migration: {目标}

### 步骤
1. [ ] 步骤1: ...
2. [ ] 步骤2: ...

### 风险
- 兼容性: {高/中/低}
- 测试覆盖: {需新增 N 个测试}

### 回滚
- git revert {commit}
```
