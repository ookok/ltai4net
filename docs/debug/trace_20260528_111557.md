## 1. 修改编译期内核配置（.config）

如果你的目标是定制一个要编译的内核（例如添加 NTFS 支持、移除不用的驱动），需要操作内核源码树中的 `.config` 文件。

### 1.1 获取内核源码并生成默认配置
```bash
# 以内核 6.1 为例
wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.1.tar.xz
tar -xf linux-6.1.tar.xz
cd linux-6.1

# 从当前运行内核复制配置（模拟已有配置）
zcat /proc/config.gz > .config   # 如果内核支持
# 或者直接用默认配置
make defconfig
```

### 1.2 使用图形界面修改（推荐）
```bash
make menuconfig   # 终端菜单界面（需要 ncurses）
# 或
make xconfig      # Qt 图形界面
# 或
make gconfig      # GTK 图形界面
```
在界面中：
- 按空格键切换选项状态：`[*]` 编译进内核，`[M]` 编译为模块，`[ ]` 不编译。
- 修改完成后选择 **Save**，会更新 `.config` 文件。

**示例：开启 NTFS 文件系统支持**
- 进入 `File systems` → `DOS/FAT/EXFAT/NT Filesystems`
- 找到 `NTFS file system support`，按 `M` 或 `*` 启用。
- 保存退出。

### 1.3 直接编辑 .config 文件（慎用）
`.config` 是纯文本，格式为 `CONFIG_选项=值`，例如：
```
CONFIG_NTFS_FS=m
CONFIG_EXT4_FS=y
# CONFIG_DEBUG_INFO is not set
```
你可以直接用编辑器修改，但必须手动处理依赖关系。修改后建议运行：
```bash
make olddefconfig   # 自动处理新选项的依赖并设置缺失的默认值
```

### 1.4 使修改生效
修改 `.config` 后需要重新编译内核、模块，并安装重启，这里不展开。通常在测试环境中：
```bash
make -j$(nproc)
make modules_install
make install
reboot
```

## 2. 修改运行时内核配置（sysctl）

这是日常管理中最常见的“内核配置文件”操作，无需重新编译，可立即生效。

### 2.1 临时修改（重启后失效）
通过 `/proc/sys/` 直接写入或使用 `sysctl -w`：

```bash
# 开启 IP 转发（让内核具备路由功能）
echo 1 > /proc/sys/net/ipv4/ip_forward
# 或
sysctl -w net.ipv4.ip_forward=1

# 调整最大文件打开数
sysctl -w fs.file-max=65536

# 启用内核的 Magic SysRq 键组合
sysctl -w kernel.sysrq=1
```

### 2.2 永久修改（写入配置文件）
主配置文件 `/etc/sysctl.conf` 和 `/etc/sysctl.d/` 目录下的 `.conf` 文件。

**示例：我正要尝试修改**（模拟操作）
```bash
# 编辑配置文件
sudo nano /etc/sysctl.d/99-my-tune.conf
```
内容改为：
```
# 开启 IP 转发
net.ipv4.ip_forward = 1

# 允许绑定非本地 IP（对负载均衡器有用）
net.ipv4.ip_nonlocal_bind = 1

# 增大连接跟踪表
net.netfilter.nf_conntrack_max = 262144

# 调整内核 printk 日志级别，抑制控制台输出
kernel.printk = 3 4 1 3
```

保存后，执行以下命令立即生效，无需重启：
```bash
sudo sysctl --system
# 或仅加载特定文件
sudo sysctl -p /etc/sysctl.d/99-my-tune.conf
```

验证修改：
```bash
sysctl net.ipv4.ip_forward
# 输出: net.ipv4.ip_forward = 1
```

### 2.3 常见可修改的内核子系统
- `kernel.*` – 主机名、SysRq、panic 行为等
- `vm.*` – swappiness、脏页比例、OOM 调整
- `net.*` – 网络栈参数（TCP 缓冲区、拥塞算法、转发等）
- `fs.*` – 文件句柄限制、pipe 容量等

## 3. 通过内核启动参数修改配置

内核还可以在启动时通过 bootloader 传递参数，这也是一种“核心配置文件”（如 GRUB 的 `GRUB_CMDLINE_LINUX`）。

例如，修改 `/etc/default/grub`：
```bash
GRUB_CMDLINE_LINUX="quiet splash iommu=pt mitigations=off"
```
然后更新 GRUB 配置：
```bash
sudo update-grub     # Debian/Ubuntu
sudo grub-mkconfig -o /boot/grub/grub.cfg   # 其他发行版
```
重启后，内核会使用这些参数初始化。

## 4. 注意事项与风险
- 修改编译期 `.config` 不当可能导致内核无法启动或缺少关键驱动。
- 运行时 `sysctl` 的某些参数直接影响稳定性（如内存管理、网络超时），建议在测试机器上先验证。
- 内核编译需要大量时间与计算资源。
- 如果只是好奇“尝试修改”，可以先用 `sysctl` 修改一个安全的参数（如 `net.ipv4.ip_forward`）来体验整个过程。
