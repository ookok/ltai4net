### 1. **内存与分配优化：走向零分配**

- **`Span<T>` / `ReadOnlySpan<T>` 作为切片利器**  
  避免 `string.Substring` 或数组拷贝，直接引用原内存区域。尤其在字符串解析、网络包处理中，能将堆分配降为零。  
  示例：用 `ReadOnlySpan<char> slice = input.AsSpan(1, 5)` 替代 `input.Substring(1, 5)`，省去新字符串分配。

- **`stackalloc` 与 `Span<T>` 配合**  
  在栈上分配临时缓冲区，绕过 GC 完全无堆分配。适用于长度不太长（< 64KB）的临时数组。C# 12 支持使用 `Span<int> buf = stackalloc int[128]` 甚至支持内联数组初始化。

- **`ArrayPool<T>` 与租用模式**  
  对于大数组高频复用场景，使用 `ArrayPool<T>.Shared.Rent(minLength)` 与 `Return`，显著降低 GC 压力。结合 `using` 和 `ref struct` 包装器（如 `Rental<T>`）自动归还，安全且优雅。

- **`string` 处理优化**  
  - 使用 `string.Create(spanAction)` 在栈上构建字符串，绕过临时对象。  
  - 针对恒定值拼接，使用 `DefaultInterpolatedStringHandler` 及自定义 handler 跳过不必要的 `ToString` 调用和装箱。  
  - 新增的 `SearchValues<string>` 可高效进行多字符串匹配，内部基于 SIMD 和向量化算法。

- **减少装箱 (Boxing)**  
  避免将值类型赋值给 `object` 或接口引用，泛型是首选。对包含值类型的 `Dictionary<TKey, TValue>`，若 TKey 是结构体，务必在实现 `IEquatable<T>` 和 `GetHashCode` 时用泛型约束，否则每次查找都会装箱。使用 `EqualityComparer<T>.Default` 能生成无装箱路径。

### 2. **结构体与 `ref struct` 的极致优化**

- **防御性拷贝 (Defensive Copy) 消除**  
  `readonly` 结构体配合 `in` 参数，可保证编译器不产生隐藏的防御性拷贝。对于可变大结构，通过 `ref readonly` 或直接传引用 `ref` 来避免拷贝。新增的 `ref readonly` 参数让意图更明确。

- **`ref struct` 的新能力**  
  C# 13 中 `ref struct` 可以实现接口（需满足一定安全规则），并可被泛型约束为 `allows ref struct`。这使高性能迭代器（如 `Span<T>.Enumerator`）能放进泛型算法，极大减少抽象开销。同时 `ref struct` 内部可以声明 `Span` 类型的字段，无需通过 `Memory<T>` 绕道。

- **`InlineArray` 特性**  
  C# 12 的 `[InlineArray]` 允许在结构体中定义固定长度的内联数组，大小嵌入类型系统，无需单独分配数组对象。例如定义 `MyBuffer` 有 1024 个 `int`，使用 `InlineArray` 后其大小即为 `1024 * sizeof(int)`，访问时完全无额外指针解引用，适合构建自定义的栈分配或嵌入缓冲区。

- **结构体设计与缓存对齐**  
  利用 `[StructLayout(LayoutKind.Sequential, Size = ...)]` 精确控制内存布局，或用 `[FieldOffset]` 手动对齐，避免伪共享（False Sharing）。配合 `Unsafe.SizeOf<T>`、`MemoryMarshal` 等方法，能进行原始内存操作而不损失安全。

### 3. **向量化与 SIMD：硬件加速的普及**

- **`System.Numerics.Vector<T>` 与向量化循环**  
  让循环自动适配硬件 SIMD 宽度。当 T 是原始数值类型时，JIT 会生成 SIMD 指令，无需手写 `Vector128` / `Vector256`。简单整数求和速度可提升 4-8 倍。

- **跨平台硬件内在函数 (`Vector128`/`Vector256`/`Vector512`)**  
  细粒度控制，直接映射到 x86 的 SSE/AVX/AVX-512、ARM 的 NEON 等。使用 `System.Runtime.Intrinsics` 命名空间。针对字符串搜索、JSON 解析等热点，手写 AVX2 版本 `IndexOf` 可比纯标量快一个数量级。  
  C# 通过 `Vector128.IsHardwareAccelerated` 等属性动态检测运行硬件，选择最佳路径。

- **`SearchValues` 与向量化匹配**  
  .NET 7/8 引入的 `SearchValues<char>` / `SearchValues<byte>` 在内部为特定字节集生成查找表或 SIMD 算法，编译时或运行时确定最佳实现。用于 URI 解析、键值分割等，比手动遍历快数倍。

- **跨平台通用 API：`Numerics.Tensors` NuGet 包**  
  提供了 `TensorPrimitives` 静态类，内含 `Sum`, `CosineSimilarity`, `SoftMax` 等操作，内部采用最优化向量化实现，适合 AI/ML 推理等场景，无需手写 SIMD。

### 4. **JIT 与编译器优化理解及利用**

- **方法内联与 `[MethodImpl(MethodImplOptions.AggressiveInlining)]`**  
  对小而频繁调用的方法标记此特性，可强制 JIT 内联，省去方法调用开销。但要避免过度使用导致方法体膨胀，削弱指令缓存。通过 `AggressiveOptimization` 标志也能提示 JIT 对特定模块开启优化，即使是 Debug 构建也有效。

- **去虚拟化 (Devirtualization) & Guarded Devirtualization**  
  JIT 对密封类（sealed）或已知具体类型的虚方法调用，会直接生成非虚拟调用。通过继承链上 `sealed` 标记和使用 `override` 配合，可让虚方法在被最终类型对象调用时完全去虚拟化，消除间接跳转并允许内联。使用 `typeof(...).IsSealed` 等设计确保层次最终封闭。

- **PGO (Profile-Guided Optimization) 动态调优**  
  .NET 6+ 支持分层编译和基于首次运行收集类型概率的 Guarded Devirtualization。PGO 能自动对常用类型进行特化，如 `foreach` 遍历 `List<T>` 时直接调用 `List<T>.Enumerator`，不走 `IEnumerator<T>` 虚表。无需手动标记，运行时自动优化。

- **常量折叠与死代码消除**  
  利用 `if (typeof(T) == typeof(int))` 等基于泛型的类型判断，JIT 会折叠为常量并移除不适用分支，生成完全特化的代码。这在写泛型数学库时非常有价值。

- **`SkipLocalsInit` 属性**  
  标记 `[SkipLocalsInit]` 避免栈初始化，当你知道 stackalloc 会立即被覆盖时，能节省初始化开销，提升性能。

### 5. **异步与 I/O 优化**

- **`ValueTask` / `ValueTask<T>` 的正确使用**  
  对于频繁完成同步的异步方法，返回 `ValueTask` 避免分配 `Task` 对象。配合 `IValueTaskSource` 高缓对象池复用，进一步提高吞吐。但要注意 `ValueTask` 不能被多次等待，需确保使用正确。

- **`System.IO.Pipelines` 数据管道**  
  通过 `PipeReader` / `PipeWriter` 处理流式 I/O（如网络传输）可动态管理缓冲区，最小化拷贝与分配。实现零拷贝时配合 `ReadOnlySequence<T>` 切片多段缓冲区，避免拼接成连续数组。

- **异步流与 `IAsyncEnumerable<T>`**  
  使用 `yield return` 异步枚举替代一次性返回集合，减少内存峰值。结合 `Channel<T>` 做生产者-消费者解耦，延迟和吞吐可兼得。注意使用 `ConfigureAwait(false)` 避开同步上下文。

- **Socket 层直接使用新型 API**  
  使用 `Socket.ReceiveFromAsync` 等接受 `Memory<byte>` 的异步 API，直接操作内存区域。甚至可以利用 `SocketsHttpHandler` 的连接池和自定义 `ConnectCallback` 实现更底层的交互。

### 6. **反射和内省的高性能替代方案**

- **源生成器 (Source Generators)**  
  彻底替代运行时代码生成和复杂反射。例如用源生成器为类型生成序列化/反序列化代码、日志记录、依赖注入绑定等。它们消除了运行时的 `Emit` 开销，并且可以提供 AOT 兼容性。.NET 8 中基于源生成器的 JSON 序列化已成为默认，性能极佳。

- **`UnsafeAccessor` 动态访问私有成员**  
  .NET 8 起，通过 `[UnsafeAccessor(UnsafeAccessorKind.Field, Name = "_field")]` 标记静态外部方法，JIT 将其编译为直接字段访问。它规避了反射和 `DynamicMethod` 的权限与性能代价，适用于需要访问内部字段的高性能场景，同时与 Native AOT 兼容。

- **`DynamicallyAccessedMembers` 与修剪安全**  
  通过精确的注解指导 IL 链接器保留所需成员，确保反射在裁剪应用中正常工作，同时最大限度缩减程序集大小。避免使用 `Assembly.GetExecutingAssembly().GetTypes()` 等非受控反射，转而使用 `TypeInfo` 和 `Type.MakeGenericType` 的已知类型参数。

### 7. **Native AOT 与部署优化**

- **提前编译（AOT）将 C# 编译为原生代码**  
  Native AOT 能大幅降低启动时间（亚毫秒）、内存占用和磁盘体积。代价是需要避免动态类型加载等限制。需要确保代码中没有无限制的泛型递归和隐式反射。使用 `<PublishAot>true</PublishAot>` 属性发布。

- **降低二进制尺寸**  
  使用 `<InvariantGlobalization>true</InvariantGlobalization>` 移除 ICU 数据，通过 `<UseSystemResourceKeys>true</UseSystemResourceKeys>` 优化异常消息，裁剪未用框架。分析使用 `ILLink.Descriptors.xml` 精细控制裁剪，移除不必要的程序集。

- **托管与原生互操作的优化**  
  采用 `LibraryImport` 源生成器（代替旧的 `DllImport`）可在编译时生成最优的 P/Invoke 桩代码，消除了运行时的 IL Stub 编译。结合 `CustomMarshaller` 可传递 `Span<T>` 到原生代码，实现零拷贝。
