### 分布式限流算法设计与C#实现

#### 1. 什么是分布式限流？
在微服务架构中，分布式限流用于保护后端服务不会因为突发流量而崩溃，同时确保资源公平分配。常见的限流算法有固定窗口、滑动窗口、令牌桶和漏桶等。本文重点对比滑动窗口和令牌桶两个经典算法，并给出基于Redis的C#分布式实现。

#### 2. 滑动窗口算法
**原理**：将时间划分为多个小的窗口段（如1秒一个窗口），记录每个窗口内的请求计数。当限流时间窗为N秒时，取当前窗口和前N-1个窗口的计数之和（或按时间比例加权）作为当前总请求数。若超过阈值则拒绝，否则通过。
- **优点**：能相对平滑地限制瞬时并发，避免固定窗口的“临界双倍”问题。
- **缺点**：需要存储多个窗口的计数，内存占用略高；在分布式环境下，需要原子性维护多个计数器。

#### 3. 令牌桶算法
**原理**：系统以恒定速率向桶中添加令牌，桶有最大容量。每个请求到达时需要消耗一个令牌，若桶中有令牌则通过，否则拒绝或等待。
- **优点**：允许一定的突发流量（桶容量大小决定了突发峰值），对流量变化的适应性更强，天然适合处理“突发后平稳”的场景。
- **缺点**：需要维护令牌生成时间，实现稍复杂，分布式环境下必须保证令牌添加和消费的原子性。

#### 4. 算法对比
| 特性 | 滑动窗口 | 令牌桶 |
|------|----------|--------|
| 突发流量处理 | 仅能限制窗口内的总量，突发可能导致窗口边界拒绝 | 允许桶容量大小的突发，更灵活 |
| 资源消耗 | 存储多个计数器，但可优化 | 仅需存储令牌数和上次填充时间 |
| 分布式复杂度 | 需要同时对多个窗口操作 | 单次原子操作即可 |
| 时间精确性 | 依赖窗口粒度 | 依赖填充时间间隔 |

#### 5. 分布式实现关键点
- **共享存储**：使用Redis集中管理限流状态，所有服务实例共享同一份数据。
- **原子操作**：使用Lua脚本保证“判断+扣减”的原子性，避免竞态。
- **时钟同步**：尽量使用Redis服务器时间或确保节点时钟同步，避免时间偏差。
- **降级策略**：当Redis不可用时，可降级为单机本地限流或直接放行（取决于业务容忍度）。

**滑动窗口实现（加权计数法）**
```csharp
public class SlidingWindowRateLimiter : IDistributedRateLimiter
{
    private readonly IDatabase _redis;
    private readonly int _precisionFactor = 10; // 窗口细分粒度，用于加权计算

    public SlidingWindowRateLimiter(IDatabase redis)
    {
        _redis = redis;
    }

    public bool TryAcquire(string resource, int maxRequests, TimeSpan window)
    {
        // 使用加权滑动窗口：上一窗口剩余比例 * 上一窗口计数 + 当前窗口计数
        string script = @"
            local key = KEYS[1]
            local max = tonumber(ARGV[1])
            local window = tonumber(ARGV[2])  -- 窗口大小，秒
            local now = redis.call('TIME')
            local currentTs = tonumber(now[1])  -- Redis服务器时间秒
            local prevWindowKey = key .. ':prev'
            local currWindowKey = key .. ':curr'

            -- 获取当前窗口起始时间
            local currWindowStart = math.floor(currentTs / window) * window
            local prevWindowStart = currWindowStart - window

            -- 读取当前窗口计数
            local currCount = tonumber(redis.call('GET', currWindowKey) or 0)
            local prevCount = tonumber(redis.call('GET', prevWindowKey) or 0)

            -- 计算加权比例
            local elapsed = currentTs - currWindowStart
            local weightPrev = 1 - (elapsed / window)
            local total = math.floor(prevCount * weightPrev + currCount)

            if total < max then
                -- 增加当前窗口计数
                redis.call('INCR', currWindowKey)
                redis.call('EXPIRE', currWindowKey, window * 2)
                return 1
            else
                return 0
            end
        ";
        var result = (int)_redis.ScriptEvaluate(script, new RedisKey[] { resource },
            new RedisValue[] { maxRequests, (int)window.TotalSeconds });
        return result == 1;
    }
}
```

```csharp
public class TokenBucketRateLimiter : IDistributedRateLimiter
{
    private readonly IDatabase _redis;
    private readonly double _rate; // 令牌生成速率（个/秒）
    private readonly int _capacity; // 桶容量

    public TokenBucketRateLimiter(IDatabase redis, double rate, int capacity)
    {
        _redis = redis;
        _rate = rate;
        _capacity = capacity;
    }

    public bool TryAcquire(string resource, int maxRequests, TimeSpan window)
    {
        // maxRequests和window用于兼容接口，实际以构造函数传入的速率和容量为准
        string script = @"
            local key = KEYS[1]
            local rate = tonumber(ARGV[1])
            local capacity = tonumber(ARGV[2])
            local now = redis.call('TIME')
            local currentTs = tonumber(now[1]) + tonumber(now[2])/1000000.0

            local bucket = redis.call('HMGET', key, 'tokens', 'last_refill_time')
            local tokens = tonumber(bucket[1]) or capacity
            local lastRefillTime = tonumber(bucket[2]) or currentTs

            local elapsed = math.max(0, currentTs - lastRefillTime)
            local newTokens = math.min(capacity, tokens + elapsed * rate)

            if newTokens >= 1 then
                newTokens = newTokens - 1
                redis.call('HMSET', key, 'tokens', newTokens, 'last_refill_time', currentTs)
                redis.call('EXPIRE', key, 60) -- 设置过期时间，避免内存泄漏
                return 1
            else
                return 0
            end
        ";
        var result = (int)_redis.ScriptEvaluate(script, new RedisKey[] { resource },
            new RedisValue[] { _rate, _capacity });
        return result == 1;
    }
}
```

#### 7. 总结
滑动窗口和令牌桶各有适用场景：当需要严格限制某个时间窗口内的总调用量时（如API配额结算），滑动窗口更合适；当需要平滑流量并允许适当突发时（如网关入口限流），令牌桶更为灵活。分布式实现的核心是共享存储+原子化Lua脚本，确保在高并发下的正确性和性能。
